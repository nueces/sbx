## Fixes found by acceptance testing

- **Mediator thread allocation:** concurrent traffic exhausted the 512 MiB virtual-address limit through glibc arena reservations despite approximately 112 MiB RSS. Set `MALLOC_ARENA_MAX=2` before mediator exec; the address-space limit and other hardening remain unchanged. A subprocess regression establishes 32 concurrent threads under that limit.
- **Premature idle expiry:** the launcher selected mitmproxy's ten-second TCP inactivity timeout, not a TCP connection-establishment timeout. Match the specified 300-second HTTP idle limit. The original timeout terminated long-running upstream HTTP/2 requests after ten seconds.
- **Idle worker recovery:** a replacement waited for a guest frame before enabling ingress, but a quiet configured guest need not transmit one. Request the guest's link address after authenticating the QEMU peer, using the netstack's ARP resolution. Readiness still requires a genuine framed guest response; no timeout or identity check is bypassed.
- **Stock-preset networking:** supply the gateway subnet through the stock image's supported kernel `ip=` argument, and install a gateway-only resolver after SSH becomes available. Otherwise the stock image selected `172.16.0.2`, making the controller's `192.0.2.2` ingress unreachable. Resolver setup failure rolls startup back.
- **Preset state and artifact locations:** use SmolVM's directory resolver before entering the temporary credential-free HOME, preserving the caller's XDG/explicit state selection. Resolve cached kernel/rootfs/initrd and SSH-key paths before that temporary HOME is removed, so persisted boot paths do not point through a deleted symlink.
- **Stale credential cleanup:** read the live guest-managed environment through SmolVM's API, not the VM configuration snapshot, before replacing/removing credential names. An installed-CLI network-disabled restart verifies both the managed profile and new shells lose the old opaque variables.
- **Benchmark fixtures:** use the address returned by the guest resolver for curl's `.localhost` targets, and pass benchmark-specific policy IDs/destinations to the mediator rather than the unrelated package-index fixture policy. Copy the benchmark's public upstream CA into each mediator's permitted state directory instead of requiring access outside Landlock's allowlist. These fixes do not add a production loopback exception or weaken confinement.

The intermittent mTLS/ingress/reuse test failures were traced to fixture descriptor ownership: `RegisterIngress` consumes a raw descriptor while the fixture retained an `os.File` that could later close a reused socket. Duplicate descriptors before transfer and retain the original files safely. The complete netstack suite then passed 100 consecutive runs. The mTLS test also has bounded waits and cleanup; no production forwarding checks were weakened.

The current dispositions are in the dated follow-ups above and the final Linux report; the list below preserves the older candidate's blockers and then-missing measurements.

1. **Dependency security:** the locked audit still reports the three Tornado 6.5.10 advisories. Current mitmproxy 12.3.1 requires Tornado `>=6.5.0,<=6.5.10`, excluding the fixed 6.6+ releases. No suppression, conflicting override or unapproved fork was introduced.
2. **Darwin amd64 wheel-only installation:** Cryptography 50.0.2 still has no usable wheel. The wheel-bearing 48.0.1 has current advisories; 49.0.0 also remains vulnerable and lacks Intel macOS wheels. A vulnerable downgrade or source-build fallback is not acceptable.
3. **Native macOS runtime:** neither native Darwin target was exercised. ARM wheel resolution and cross-built workers are not native execution evidence.
4. **Reference performance:** run readiness p95 ≤1 second, idle pair RSS p95 ≤256 MiB/512 MiB ceiling, HTTPS ≥100 Mbit/s and ≥50% SLIRP, added established p95 latency ≤10 ms, sustained concurrency, and four-VM acceptance on the required reference environment. Local diagnostic results cannot renew the former waivers. Rootless Docker here lacks a cgroup driver, so a claimed 8-GiB container limit would not establish that environment. The isolated full benchmark progressed past its fixture DNS/policy/CA failures, but an established keep-alive request still timed out. It did not produce accepted throughput/latency/SLIRP results; that failure still needs diagnosis.
5. **Complete preset bootstrap:** the campaign's stock-image networking was reachable, but the non-root stock preset lacked `visudo`; a separate root-user attempt hit its provisioning timeout under the deliberately restricted bootstrap policy. The subsequent candidate now uses the prepared Debian `sbx` base (including `sudo`/`visudo`) and skips redundant stock OS-package setup. This source change is unit-tested, not a new live acceptance result; complete a prepared-image/policy run and rebuild/revalidate the final wheel. Do not silently switch users or broaden production policy to turn these into passes.
6. **Complete evidence:** actual FD enumeration is unavailable for nondumpable children, not zero. License inventory and missing metadata were inspected, but complete bundled/transitive notice acceptance and remaining final operator/fault/performance scenarios must have explicit results.

A failed or unavailable required gate remains a blocker. Do not infer full acceptance from the aggregate test count or from any individual successful smoke test.
